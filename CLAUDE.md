## Architecture

### File Structure

```
src/
  app/
    page.tsx              # Homepage (client component, shows auth state)
    layout.tsx            # Root layout with ConvexClientProvider
    globals.css           # Tailwind v4 entry (@import "tailwindcss")
    callback/route.ts     # WorkOS auth callback handler
    sign-in/route.ts      # Redirects to WorkOS sign-in
    sign-up/route.ts      # Redirects to WorkOS sign-up
    sign-out/route.ts     # Clears session + redirects to WorkOS logout
  components/
    ErrorBoundary.tsx     # Class component, wraps Convex provider
    providers/
      ConvexClientProvider.tsx  # AuthKitProvider → ConvexProviderWithAuth → UserSync
      UserSync.tsx              # Syncs WorkOS user to Convex users table on auth
  hooks/
    useCurrentUser.ts     # Returns { user, isLoading, isAuthenticated, isAdmin }
  lib/
    env.ts                # Zod validation of NEXT_PUBLIC_* env vars at import time
    utils.ts              # slugify(), formatDate()
    utils.test.ts         # 8 tests for utils
  middleware.ts           # WorkOS authkitMiddleware protecting /admin/* routes
  test/
    setup.ts              # @testing-library/jest-dom setup

convex/
  schema.ts               # posts, users, post_revisions tables
  posts.ts                # Public: getPublished, getBySlug. Admin: getAll, getById, create, update, remove, updateStatus
  users.ts                # current (query), syncFromWorkOS (mutation)
  auth.config.ts          # WorkOS JWT validation config for Convex
  lib/
    auth.ts               # getCurrentUser, requireAuth, requireAdmin helpers
  _generated/             # Auto-generated by Convex (committed to git)
```

### Key Design Decisions

- **Status enum over boolean** — `"draft" | "published" | "archived"` avoids migration when adding states later
- **Pre-edit revision snapshots** — `update` mutation saves the CURRENT state BEFORE applying changes (audit trail of previous states, not changes)
- **Slug immutability after publish** — prevents URL breakage, `firstPublishedAt` is set once and never cleared
- **Pagination from day one** — all listing queries use `.paginate()` with `paginationOptsValidator`
- **Server-side identity validation** — `syncFromWorkOS` verifies `identity.subject === args.workosId`
- **First user is admin** — safe from TOCTOU because Convex mutations are serialised

### Auth Flow

1. User clicks sign-in/sign-up → `<a>` tag navigates to route handler → redirects to WorkOS hosted UI
2. WorkOS authenticates → redirects to `/callback` → `handleAuth()` sets session cookie
3. `ConvexClientProvider` wraps `AuthKitProvider` → `ConvexProviderWithAuth` with custom `useAuthFromAuthKit` hook
4. `UserSync` component calls `syncFromWorkOS` mutation on auth, writing user to Convex `users` table
5. Sign-out: `<a>` to `/sign-out` route → calls `signOut({ returnTo })` → clears cookie + redirects to WorkOS logout → WorkOS redirects back to app

### Auth Links Pattern

All auth links (sign-in, sign-up, sign-out) use `<a>` tags pointing to route handlers, NOT `<Link>`:

- These routes redirect externally (to WorkOS), so Next.js client-side navigation via `<Link>` causes CORS/fetch errors
- `<a>` does full-page navigation which correctly follows the redirect chain

## Known Issues / Gotchas

- **Next.js 16 middleware deprecation**: `"middleware" file convention is deprecated, use "proxy" instead` — this is a warning only. WorkOS AuthKit relies on middleware; no action needed until authkit-nextjs updates.
- **`next lint` removed in Next.js 16**: The `next lint` subcommand was intentionally removed. The `next` CLI interprets `lint` as a project directory path, causing "Invalid project directory" errors. We use `eslint src/` directly — this is the documented migration path.
- **Convex `_generated/` is committed**: These auto-generated types must be in git for CI builds and type resolution.
- **`.prettierignore` excludes `convex/_generated`**: Auto-generated files don't match our formatting rules.
- **4 low-severity npm audit vulns**: Transitive `cookie` dependency in WorkOS SDK. Not actionable on our end.
